# AGENTS

## Layout

- `lua/sundial/colors/{last,first}.lua` — palettes. These are the source of truth.
- `lua/sundial/colors/init.lua` — derives diff, UI, and terminal colors.
- `lua/sundial/groups/` — editor, syntax, markup, and plugin highlight groups.
- `colors/{last,first}-light.lua` — Neovim entry points and scheme names.
- `after/queries/` — Tree-sitter extensions for Markdown tables and YAML keys.
- `assets/sundial.svg` — the logo used at the top of the README.
- `assets/screenshots/` — images used by the README, generated by `scripts/screenshots/`.
- `scripts/{kitty,vscode,opencode}.lua` — generators for `extras/`.
- `scripts/screenshots/` — README image generator and checker. Not part of the plugin.
- `extras/kitty`, `extras/vscode`, `extras/opencode` — generated output. Never edit by hand.
- `tests/smoke.lua` — headless checks for both schemes and the options API.
- `tests/contrast.lua` — contrast checks for default opaque editing states.

## Rules

- Change palettes or groups first; regenerate `extras/` afterwards.
- Keep the scheme names `last-light` and `first-light`; `sundial` is the plugin.
- Add plugin highlights to `groups/plugins.lua`. Names are inert until the plugin
  uses them, so the theme never loads a plugin.
- A new scheme needs a palette in `colors/`, an entry point in `colors/`, and
  the name mapping in `theme.lua` plus `tests/smoke.lua`.
- Never commit identifiable personal information in files, screenshots, or
  logs: real names, email addresses, home-directory paths, hostnames,
  usernames, tokens, or credentials. Review `git diff --cached` before every
  commit.

## Sync Neovim with the extras

Run from the repository root after any palette or group change:

```sh
nvim --headless -u NONE -n -i NONE -l scripts/kitty.lua
nvim --headless -u NONE -n -i NONE -l scripts/vscode.lua
nvim --headless -u NONE -n -i NONE -l scripts/opencode.lua
nvim --headless -u NONE -n -i NONE -l tests/smoke.lua
```

Then review the generated files:

```sh
git diff extras/
```

The Kitty conf, the VS Code / Hermes JSON, and the OpenCode theme JSON must
match the palettes: all of them read `colors.terminal` and the same semantic
colors, so a manual edit in `extras/` will be overwritten by the next generator
run.

Install surfaces:

- Kitty: include `extras/kitty/<scheme>.conf` from `kitty.conf`.
- VS Code: `code --extensionDevelopmentPath="$PWD/extras/vscode"`.
- Hermes: import the published VS Code theme, or paste the JSON where the
  Desktop importer accepts theme text.
- OpenCode: copy `extras/opencode/<scheme>.json` into
  `~/.config/opencode/themes/` and select it with `/themes`.

## Regenerate the README screenshots

`assets/screenshots/` is generated, and `scripts/screenshots/` explains how it
works. After a palette, group, or demo-buffer change:

```sh
scripts/screenshots/setup.sh     # only once: plugins into ~/.cache
scripts/screenshots/render.py --all
scripts/screenshots/verify.py
```

Rendering is byte-reproducible, so `verify.py` fails if a committed image is
stale. It needs Python with Pillow and msgpack plus JetBrainsMono Nerd Font;
CI does not run it, so images are refreshed by hand.

## CI

`.github/workflows/ci.yml` runs on push and pull request:

- `stylua --check` over `lua/`, `colors/`, `scripts/`, and `tests/`.
- The smoke test on Neovim `v0.10.4`, `stable`, and `nightly`.
- The contrast test on the same versions, with a 4.5:1 floor for the checked text pairs.
- Regenerates the Kitty, VS Code, and OpenCode extras and fails if `extras/`
  changed, then validates the JSON.

Run the same checks locally before pushing:

```sh
npx --yes @johnnymorganz/stylua-bin@2 --check lua colors scripts tests
nvim --headless -u NONE -n -i NONE -l tests/smoke.lua
nvim --headless -u NONE -n -i NONE -l tests/contrast.lua
nvim --headless -u NONE -n -i NONE -l scripts/kitty.lua
nvim --headless -u NONE -n -i NONE -l scripts/vscode.lua
nvim --headless -u NONE -n -i NONE -l scripts/opencode.lua
git diff --exit-code -- extras
```
